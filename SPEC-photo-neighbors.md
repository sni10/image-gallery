# ТЗ: соседние фото в `GET /photos/{photo_id}`

## Зачем

На странице фото (`/photos/:id`) появляются стрелки «предыдущее / следующее». Они ведут на соседние фото
**той же галереи**, в том же порядке, в каком фото идут в `GET /galleries/{id}/photos` (сначала новые, `-id`).
Сейчас фронт узнать соседей не может: для этого пришлось бы выкачать все фото галереи.

## Что добавить в ответ `GET /photos/{photo_id}`

Два поля:

| Поле | Тип | Значение |
| --- | --- | --- |
| `prevId` | `string \| null` | Публичный id фото, которое в списке галереи стоит **перед** текущим (более новое). `null`, если текущее фото первое |
| `nextId` | `string \| null` | Публичный id фото, которое стоит **после** текущего (более старое). `null`, если текущее фото последнее |

```json
{
  "id": "…", "title": "…", "…": "…",
  "gallery": { "id": "…", "title": "Cats", "category": { "id": "…", "slug": "ai", "title": "AI" } },
  "prevId": "…",
  "nextId": null
}
```

- Порядок должен совпадать с `GET /galleries/{id}/photos`. Если порядок фото в галерее когда-нибудь поменяется,
  соседи меняются вместе с ним.
- Соседи ищутся только внутри галереи текущего фото, через границу галереи не переходят.
- Нужно два лёгких запроса по индексу, без выборки всей галереи. Например, при порядке `-id`:
  - prev: `gallery.photos.filter(id__gt=photo.id).order_by('id').values_list('public_id', flat=True).first()`;
  - next: `gallery.photos.filter(id__lt=photo.id).order_by('-id').values_list(...).first()`.
- Описать оба поля в OpenAPI: `help_text`, nullable.
- Изменение не ломает API: старые клиенты новые поля просто игнорируют.

## Тесты

- Галерея из трёх фото A (новое), B, C (старое):
  - у A `prevId = null`, `nextId = B`;
  - у B `prevId = A`, `nextId = C`;
  - у C `prevId = B`, `nextId = null`.
- Фото из соседней галереи никогда не попадает в `prevId` / `nextId`.
- У единственного фото галереи оба поля `null`.

Сообщение для коммита: `feat(api): expose previous and next photo ids in photo detail`.

## Дальше (не входит в эту задачу)

Теги под фото на фронте пока выводятся заглушками без клика. Потом клик по тегу будет открывать фото с этим тегом.
Для этого понадобится список фото по тегу с пагинацией, как у остальных списков (например `GET /photos?tag=<tag>`).
Отдельное ТЗ напишу, когда до этого дойдём.

## Фронт

Фронт уже читает `prevId` / `nextId`. Пока полей нет, стрелки просто не показываются.
