# gallery-categories Specification

## Purpose
Категории галерей: каждая галерея относится ровно к одной категории, посетитель может смотреть каталог по категориям, администратор управляет категориями и раскладывает по ним галереи.

## Requirements

### Requirement: Галерея принадлежит ровно одной категории
Каждая галерея SHALL иметь ровно одну категорию. Создать или сохранить галерею без категории MUST быть невозможно. Категорию, в которой есть галереи, MUST быть невозможно удалить.

#### Scenario: Галерея без категории
- **WHEN** администратор сохраняет галерею, не выбрав категорию
- **THEN** галерея не сохраняется, форма показывает ошибку у поля категории

#### Scenario: Удаление непустой категории
- **WHEN** администратор удаляет категорию, в которой есть галереи
- **THEN** категория не удаляется, админка сообщает, какие галереи мешают

### Requirement: Атрибуты категории
Категория SHALL иметь название, уникальный slug из латинских букв в нижнем регистре, цифр и дефисов, и целочисленную позицию для порядка вывода. Slug MUST быть уникальным.

#### Scenario: Неверный или занятый slug
- **WHEN** администратор сохраняет категорию со slug `Комиксы!` или со slug, который уже есть
- **THEN** категория не сохраняется, форма показывает ошибку у поля slug

### Requirement: Список категорий
Система SHALL отвечать на `GET /categories` `200` с массивом `[{ "id": "<строка>", "slug": "...", "title": "...", "galleriesCount": <число> }]`. В ответ MUST попадать только категории, в которых есть хотя бы одна галерея. Порядок MUST быть по позиции, при равной позиции — по названию. Эндпоинт MUST быть доступен без авторизации.

#### Scenario: Пустые категории скрыты
- **WHEN** есть категории «AI» (3 галереи), «Комиксы» (1 галерея) и «Фото» (0 галерей)
- **THEN** ответ содержит «AI» с `galleriesCount: 3` и «Комиксы» с `galleriesCount: 1`, «Фото» в ответе нет

#### Scenario: Порядок вывода
- **WHEN** у «Комиксы» позиция 1, у «AI» позиция 2
- **THEN** «Комиксы» идёт в ответе раньше «AI»

### Requirement: Каталог галерей по категории
`GET /galleries` SHALL принимать необязательный параметр `category` со slug категории и возвращать только галереи этой категории, с той же пагинацией, порядком и форматом, что и без фильтра. Без параметра MUST возвращаться все галереи, как раньше. Для slug несуществующей категории MUST возвращаться `200` с `{ "items": [], "total": 0 }`.

#### Scenario: Фильтр по категории
- **WHEN** запрос `GET /galleries?category=ai`
- **THEN** в `items` только галереи категории `ai`, `total` равен их числу

#### Scenario: Без фильтра
- **WHEN** запрос `GET /galleries` без `category`
- **THEN** в ответе галереи всех категорий

#### Scenario: Неизвестная категория
- **WHEN** запрос `GET /galleries?category=nope`
- **THEN** ответ `200` с `{"items": [], "total": 0}`

### Requirement: Категория в объекте галереи
Объект `Gallery` в ответах `GET /galleries` и `GET /galleries/{id}` SHALL содержать поле `category` с `{ "id": "<строка>", "slug": "...", "title": "..." }`. Поле MUST всегда быть заполнено.

#### Scenario: Галерея с категорией
- **WHEN** запрос `GET /galleries/{id}` для галереи из категории «Комиксы»
- **THEN** в ответе `category` с `slug: "comics"` и `title: "Комиксы"`

### Requirement: Управление категориями в админке
Админка SHALL позволять создавать, редактировать и удалять категории, задавать позицию и slug (с автозаполнением из названия, в том числе с транслитерацией кириллицы). На странице галереи категория MUST выбираться обязательным полем. Список галерей MUST показывать категорию и позволять фильтровать по ней.

#### Scenario: Перенос галереи в другую категорию
- **WHEN** администратор меняет категорию на странице галереи и сохраняет
- **THEN** галерея появляется в каталоге новой категории и пропадает из старой

#### Scenario: Фильтр в списке галерей
- **WHEN** администратор выбирает в фильтре списка галерей категорию «AI»
- **THEN** список показывает только галереи категории «AI»
