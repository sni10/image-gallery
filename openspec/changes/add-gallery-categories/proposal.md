## Why

Галерей становится больше, и они разные по содержанию: AI-картинки, комиксы и т. д. Посетителю нужен способ смотреть только интересный ему тип, а администратору — способ раскладывать галереи по разделам.

## What Changes

- Новая сущность «Категория»: название, slug для адреса (`ai`, `comics`), порядок вывода.
- Каждая галерея принадлежит ровно одной категории; галерея без категории невозможна.
- `GET /categories` — список непустых категорий в заданном порядке, с числом галерей.
- `GET /galleries?category=<slug>` — каталог галерей одной категории; без параметра каталог работает как раньше.
- В объекте `Gallery` (каталог, `GET /galleries/{id}`) появляется поле `category`.
- Админка: раздел категорий (создание, порядок, slug с автозаполнением из названия), обязательный выбор категории на странице галереи, колонка и фильтр по категории в списке галерей. Категорию с галереями удалить нельзя.
- Существующие галереи, фото и избранное обнуляются перед обновлением (решение владельца: контент перезаливается), поэтому миграция просто добавляет обязательную категорию без переноса данных.

Вне рамок: фильтр случайных фото главной (`GET /photos`) по категории, несколько категорий у галереи, вложенные категории.

## Capabilities

### New Capabilities
- `gallery-categories`: категории галерей, их список в API, фильтр каталога по категории, категория в объекте галереи, управление категориями в админке.

## Impact

- **Бэкенд:** модель `Category` и обязательная связь `Gallery.category` в приложении `gallery`; миграция с обязательной категорией; `GalleryQueries`, `GallerySerializer`, новые вьюхи/маршрут `/categories`, фильтр в `GalleryListView`; админка категорий и галерей; тесты и OpenAPI.
- **Данные:** галереи, фото (включая файлы в `media/`) и избранное в базе compose удаляются; пользователи остаются.
- **Фронтенд (`image-gallery-front`):** вкладки или фильтр категорий в каталоге, возможно отдельный адрес категории; поле `category` у галереи.
