## Why

API и ссылки сайта показывают автоинкрементные id из БД (`/galleries/8`, `id: "79"` у фото, `id` пользователя в `/me`, `sub` в JWT, `uid` в ссылках из писем). По ним видно число записей и порядок их создания, их можно перебирать, а распространившуюся ссылку на галерею нельзя отозвать. Нужны непрозрачные идентификаторы, которые администратор может перевыпустить.

## What Changes

- **BREAKING:** во всех ответах API поле `id` у галереи, фото, категории и пользователя — непрозрачный публичный идентификатор вместо номера из БД. Пути `/galleries/{id}`, `/galleries/{id}/photos`, `/me/favorites/{photoId}` принимают только публичный идентификатор; числовой id даёт 404.
- Публичный идентификатор — хеш от внутреннего id, «даты ссылки» записи и секрета сервера. Подобрать или вычислить его по номеру нельзя.
- У галереи, фото, категории и пользователя появляется отдельное поле «дата ссылки», изначально равное дате создания записи (для существующих записей — тоже). Дата создания при этом не меняется.
- Смена даты ссылки в админке (или кнопка «перевыпустить» — текущее время) меняет публичный идентификатор; старый сразу перестаёт работать (404).
- JWT (`sub`) и токены в письмах (`uid`) содержат публичный идентификатор пользователя вместо номера из БД. **BREAKING:** выданные до обновления access-токены и ссылки из писем перестают работать (access живёт 15 минут, refresh-токены продолжают работать).

Вне рамок: админка продолжает использовать внутренние id в своих URL (она закрыта); slug категорий остаётся как есть; редирект со старого идентификатора на новый не делается.

### New Capabilities
- `public-ids`: непрозрачные публичные идентификаторы сущностей в API и токенах, дата ссылки и перевыпуск идентификатора.

## Impact

- **Бэкенд:** поля `link_date` и `public_id` у `Gallery`, `Photo`, `Category`; новая модель профиля пользователя (`accounts.Profile`) для его даты ссылки и публичного id; миграции с заполнением для существующих записей; все сериалайзеры и вьюхи с id; поиск по публичному id в путях; `AccessTokenService`, `BearerAccessTokenAuthentication`, `EmailTokenService`; админка (поле даты и действие «перевыпустить ссылку» у галерей, категорий, пользователей; для фото — действие в сетке галереи); тесты и OpenAPI.
- **Фронтенд:** формат `id` меняется (строка, но не число) — ссылки вида `/galleries/<id>` продолжают строиться из `id` без изменений кода, если фронт нигде не полагается на числовой вид. Закешированные/сохранённые старые ссылки станут 404.
- **Данные:** существующие записи получают дату ссылки = дате создания и публичный id; данные не удаляются.
