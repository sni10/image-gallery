## Why

На фронте под фото уже выводятся теги-заглушки. Клик по тегу должен открывать главную со всеми фото этого тега
вместо случайной ленты. Сейчас API отфильтровать фото по тегу не умеет.

## What Changes

- `GET /photos` получает необязательный параметр `tag`: при нём в ленту попадают только фото с этим тегом, порядок
  по `seed` и пагинация те же.
- Тег из запроса нормализуется так же, как при загрузке (обрезка пробелов, без `#`, нижний регистр).
- Неизвестный тег даёт пустую страницу (200, `total: 0`), а не 404.
- GIN-индекс на `Photo.tags`, чтобы фильтр не перебирал всю таблицу.
- Теги остаются массивом в фото, отдельной модели Tag нет.
- Не входит: модель Tag, страницы тегов, список тегов с количеством фото.

## Capabilities

### New Capabilities
- `photo-tags`: фильтр общей ленты фото по тегу.

### Modified Capabilities

## Impact

- Бэкенд: `RandomPhotoListView`, `PhotoQueries`, миграция с индексом, OpenAPI-описание параметра.
- API обратно совместим: без `tag` ответ прежний.
- Фронт (отдельный репозиторий): клик по тегу ведёт на `/?tag=<tag>`, главная передаёт `tag` в `GET /photos`.
