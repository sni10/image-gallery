# ТЗ: водяной знак ArtAI.win на полноразмерных картинках

## Решения

- На каждую полноразмерную картинку, которую видят посетители, накладывается текст **`ArtAI.win`** в одном из четырёх
  углов (выбирается по хешу картинки: случайный, но стабильный), с отступом от края: полупрозрачный белый с тёмной обводкой, высота шрифта 4% короткой стороны (не меньше 12 px).
- Превью (`thumb/`, WebP 400 px) остаются без знака.
- Знак накладывается **один раз при загрузке**, а не на лету: файлы отдаются как статика с вечным кэшем.
- Чистый оригинал хранится **вне `/media`**, в отдельном томе, который видит только `app`. Caddy его не отдаёт.
- Анимированные GIF/WebP остаются без знака: метить каждый кадр пока не нужно.

## Готово

`gallery/services/watermark.py` — независимый модуль: только Pillow, без Django и импортов проекта.

- `watermark(data: bytes) -> bytes`. Формат сохраняется. Поворот из EXIF применяется к пикселям до наложения,
  иначе у повёрнутых фото знак оказался бы не в том углу. ICC-профиль сохраняется. Для одного и того же входа
  выход всегда одинаковый.
- Запуск как скрипт: пройти по всем существующим картинкам, отложить чистые копии и наложить знак (см. «Выкатка»).
- Тесты: `gallery/tests/test_watermark.py`.

## Схема хранения

| Что | Где | Кто видит |
| --- | --- | --- |
| Картинка со знаком | `media/original/ab/cd/<sha256>.<ext>` (как сейчас) | Caddy отдаёт её по `api.artai.win/media/...` |
| Чистый оригинал | `originals/original/ab/cd/<sha256>.<ext>` | только `app` |
| Превью | `media/thumb/ab/cd/<sha256>.webp` (как сейчас) | все |

`<sha256>` по-прежнему считается от **чистого** оригинала (после удаления метаданных). Поэтому:

- миграция БД не нужна: `Photo.image.name` и адреса картинок не меняются;
- дедупликация в `get_or_create` и `store_once` работает как раньше: одинаковое имя значит одинаковый чистый
  источник, а значит и одинаковый результат со знаком;
- путь к чистой копии вычисляется из `Photo.image.name`, отдельное поле в модели не нужно.

## Изменения в коде

1. **Настройки.** `MediaSettings.originals_root: Path = Path('originals')` (env `MEDIA_ORIGINALS_ROOT`)
   → `settings.ORIGINALS_ROOT`. Хранилище для чистых копий: `FileSystemStorage(location=ORIGINALS_ROOT)`,
   без `base_url`, потому что наружу эти файлы не отдаются.
2. **`PhotoService._store`.**
   - В `photo.image` пишется `watermark(processed.original)` под тем же именем `original_name(processed)`.
   - Рядом в хранилище оригиналов пишется `processed.original` по пути `photo.image.name`, если его там ещё нет.
   - Превью и размеры не меняются.
3. **`PhotoService.rebuild_thumb`.** Читать из чистой копии, а не из `photo.image`, иначе знак попадёт в превью,
   и хеш будет посчитан от картинки со знаком. Если чистой копии нет (фото до перехода, по которому ещё не прошёл
   скрипт), берётся `photo.image`.
4. **Сигнал `post_delete`** (`gallery/signals.py`). Когда на файл картинки больше никто не ссылается, удалять и
   её чистую копию.
5. **`compose.prod.yaml` и `compose.yaml`.** Новый том `originals:/app/originals`, подключённый **только к `app`**.
   Caddy его не монтирует.

## Тесты

- После загрузки (`create` / `get_or_create` / ingest API) файл в `media` отличается от присланного, а в
  `originals` лежит чистый оригинал.
- Повторная загрузка той же картинки не создаёт дублей ни в `media`, ни в `originals`.
- `rebuild_thumb` строит превью из чистой копии: в превью знака нет.
- Удаление фото удаляет и чистую копию, если её не использует другое фото.

Сообщение для коммита: `feat(gallery): watermark full-size images on upload, keep clean originals private`.

## Выкатка

1. Деплой кода и нового тома (`deploy/deploy.sh <sha>`). С этого момента новые загрузки, в том числе из ComfyUI,
   получают знак.
2. Пробный прогон по старым картинкам на сервере, без изменений:

   ```
   cd /srv/artai && docker compose -f compose.prod.yaml exec app python gallery/services/watermark.py /app/media/original /app/originals/original --dry-run
   ```
3. Боевой прогон: та же команда без `--dry-run`. Скрипт:
   - копирует чистый оригинал в `/app/originals/...`, потом атомарно заменяет публичный файл версией со знаком;
   - не трогает уже помеченные файлы, поэтому его можно прервать и запустить снова;
   - пропускает анимированные файлы и печатает итог: `marked`, `done`, `animated`, `failed`.
4. **Cloudflare → Caching → Purge Everything.** У `/media/*` стоит `Cache-Control: immutable` на год, и без очистки
   Cloudflare продолжит отдавать чистые версии. У тех, кто уже смотрел сайт, браузеры какое-то время будут
   показывать старые картинки из своего кэша, это допустимо.
5. Проверка: открыть любую картинку по `url` из API, на ней должен быть знак, а превью без него.

## Смена знака в будущем

Поменять константы в `watermark.py`, задеплоить, затем запустить скрипт с `--force` (перерисует все публичные
файлы из чистых копий, без двойного знака) и снова сделать Purge Everything в Cloudflare.

## Риски

- Чистые оригиналы есть только в томе `originals` на сервере. Бэкапы пока отложены, поэтому если том потерять,
  останутся только версии со знаком.
- Повторное сжатие JPEG (качество 95) и WebP (95) немного теряет качество. PNG сжимается без потерь.
